# MIRROR Chrome extension

Chrome (Manifest V3) side panel that shows the existing React app from `../frontend`, plus an optional
"Read from ChatGPT / Claude" button. `ui/` is **generated** by the frontend build. Never edit it by hand.

## Folder layout
```
project/
├── frontend/            React app (single source of truth for the UI)
├── backend/             your backend (not included in the files I received)
└── mirror-extension/
    ├── manifest.json    MV3 manifest, side panel = ui/index.html
    ├── background.js    service worker: icon click opens the side panel
    ├── content.js       passive page reader for chatgpt.com / claude.ai
    ├── icons/           16/48/128 px icons
    └── ui/              GENERATED by `npm run build:extension` (git-ignored)
```

## Setup (Windows, PowerShell)
```powershell
cd path\to\project\frontend
npm install
npm run build:extension      # writes ..\mirror-extension\ui\
```
Then in Chrome: `chrome://extensions` → turn on **Developer mode** → **Load unpacked** → select the
`mirror-extension` folder (the one containing `manifest.json`). Pin the MIRROR icon and click it.
The side panel opens directly (no popup). Requires Chrome 116+.

## After changing code
* Changed anything in `frontend/src`: run `npm run build:extension`, then click the reload icon on the MIRROR card in
  `chrome://extensions`, then close and reopen the side panel.
* Changed `manifest.json`, `background.js` or `content.js`: reload the extension, then **reload the ChatGPT/Claude tab**
  (old tabs keep the previous content script).
* `npm run dev` still runs the normal website at localhost:5173, independent of the extension.

## The two input modes
**Manual:** unchanged. Paste a response (and optionally the prompt), press Analyze.

**Capture:** with a chatgpt.com or claude.ai conversation in the active tab, click **Read from ChatGPT/Claude**.
The side panel asks the page's content script for the conversation's prompt/reply pairs, lists them (newest first),
and fills the editable fields with the newest one. Click another reply to use that one, **Refresh** to re-read.
Edit as you like, then press **Analyze** yourself. Reading happens only on your click, only in the active tab,
and captured text is held in memory only. It is dropped when you switch tabs or conversations and is never written
to storage. If capture fails, the manual form keeps working.

Messaging: side panel ⇄ content script directly via `chrome.tabs.sendMessage` (the content script ignores any
sender that is not this extension). The service worker never sees conversation text.

Permissions: `sidePanel`; host access to chatgpt.com, claude.ai, localhost:8000 and 127.0.0.1:8000 only.
The backend URL in Settings must stay on one of those hosts; any other URL needs a matching `host_permissions`
entry (or CORS on that server).

## Testing checklist (needs a real Chrome, not yet run by me)
For each of ChatGPT and Claude:
- [ ] Icon click opens the side panel with no popup.
- [ ] On an unsupported tab (e.g. google.com) the panel says to open ChatGPT/Claude; manual form works.
- [ ] Open a conversation with 2+ replies: the button says "Read from ChatGPT/Claude" and the list shows every reply once.
- [ ] Newest reply and its prompt appear in the editable fields; prompt box is expanded.
- [ ] Pick an older reply: fields update to it.
- [ ] Ask a new question, click Refresh: new reply appears, no duplicates.
- [ ] Click while a reply is streaming: "Still generating" warning shows; Refresh after it ends fixes it.
- [ ] Regenerate a reply, then Refresh: only the visible version is listed.
- [ ] Switch to another conversation/tab: the list clears (fields keep your text).
- [ ] New empty chat: "No assistant reply found" message.
- [ ] Open the tab before loading/reloading the extension: "Reload the tab" message, then works after reload.
- [ ] Backend stopped: header says "Backend offline"; Analyze shows a connection error, nothing fake appears.
- [ ] Backend running: Analyze returns a real result in the report/counterfactual tabs.
- [ ] Confirm in DevTools → Network that nothing is sent to localhost:8000 until you press Analyze.

## Backend integration
**Not verified.** No `backend/` folder was included, so the contract below is the one already assumed in
`frontend/src/services/api.js`. Compare it with your real routes:
```
GET  /health   -> 200                      (used only for the "Backend connected/offline" badge)
POST /analyze  { response: string, prompt: string|null }
            -> { label, confidence: number, probabilities: { <label>: number }, cue?: string,
                 counterfactual?: { text, prompt?, still_biased?, similarity?, drift? } }
labels: gender, caregiver_role, decision_authority, socioeconomic_class, none
```
Remaining work: confirm those fields against the backend; if there is no `/health` route, add one or change
`checkHealth` in `api.js` (the badge will show "offline" even if `/analyze` works). All changes belong in
`api.js`; the UI does not need to change. Requests from the side panel are allowed by `host_permissions`, so no
CORS setup is needed for the extension (the website at localhost:5173 still needs CORS).
